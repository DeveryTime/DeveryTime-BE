# 게시글 이미지 교체 및 본문 저장 흐름

이 문서는 PR #99의 동작을 설명한다. 현재 배포된 API에 적용되기 전이다.

1. 클라이언트가 `PUT /api/posts/{id}/images/{imageId}`에 `multipart/form-data`의 `file` 파트로 새 이미지 한 장을 전송한다.
2. 응답의 `data.imageUrl`로 편집 중인 본문의 이미지 주소를 바꾼다.
3. 클라이언트가 `PUT /api/posts/{id}`에 현재 `title`과 변경된 `content`를 함께 보내 본문을 저장한다. URL만 수정하는 경우에도 `title`은 필수다.

이미지 교체 요청이 성공해도 본문은 자동으로 수정되지 않는다. 서버는 저장하지 않은 편집 내용이 이전 이미지를 참조할 수 있으므로 이전 파일을 즉시 삭제하지 않는다. 본문 저장이 성공하고 더 이상 이전 URL을 참조하지 않으면 그 파일을 정리한다. 게시글이 삭제되면 이전 파일도 정리한다. 본문을 저장하지 않거나 게시글을 삭제하지 않으면 이전 파일과 정리 기록이 유지될 수 있다.

본문 저장이 실패하면 이전 URL을 포함한 본문이 계속 동작하도록 이전 파일을 보존한다. 사용자는 본문을 수정하고 저장을 다시 시도할 수 있다.
